What it does

Everything a bucket needs to earn its name

Built for a single fixed-credential account with multi-bucket support — not a multi-tenant platform. If that's your shape, this covers the essentials.

REST API

S3-compatible core

Bucket and object CRUD, ListObjectsV2-style listing, Range requests, and full object versioning.

Auth

Real AWS SigV4

Requests sign with the actual AWS4-HMAC-SHA256 spec, auto-detected alongside the project's own scheme — no SDK patching.

Uploads

Presigned URLs

Direct browser upload/download without routing bytes through your app server.

Pipeline

Validation & scanning

Size/MIME checks, optional ClamAV virus scanning, and automatic image thumbnailing on write.

Events

Webhooks, S3-shaped

Every write/delete queues an event; webhook payloads match real S3 Event Notifications, so existing consumers work unchanged.

Access

Per-bucket policy

CORS, public-read buckets, size caps, and MIME allowlists — configured per bucket, like real S3.

Delegation

Short-term tokens

Issue scoped, time-limited tokens for a single bucket — no need to hand out the real access key.

Operations

Admin panel

Bucket management, an object tree browser with inline preview, and event status with manual redispatch — separate login from the API.

Authentication

Two schemes, auto-detected per request

Sign with whichever fits — the server figures out which scheme a request used and verifies it accordingly.

AWS4-HMAC-SHA256

The real SigV4 spec

Unmodified AWS SDKs authenticate exactly as they would against AWS — set endpoint and forcePathStyle: true, keep your existing code.

OS3-HMAC-SHA256

This project's own scheme

Header or presigned-URL query auth for clients calling the API directly, without pulling in a full AWS SDK.

Deployment

Three ways to run it — same app, same database

Pick the one that matches your infrastructure. Options 1 and 2 are Docker; option 3 needs nothing but a cPanel-style shared host.

Option 1 — nginx Option 2 — Apache Option 3 — shared hosting
Web server nginx + PHP-FPM Apache + mod_php Whatever your host runs
Event worker Long-running daemon (near-instant) Cron every minute HTTP-triggered drain via cron wget
Redis Required Required Not available — events read straight from the database
Docker Yes Yes None at all
Best for Lowest event latency, standard ops Simpler single-process container You only have cPanel-style hosting

Architecture

What talks to what

MySQL and Redis are external dependencies this project connects to — not something the stack provisions itself.

nginx (8080) ─┬─→ app (PHP-FPM, CodeIgniter 3) ──┬─→ MySQL │ │ └─→ worker (CLI, Redis consumer) ───┴─→ Redis
